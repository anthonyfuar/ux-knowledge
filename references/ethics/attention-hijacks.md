# Attention hijacks and their counter-patterns

## Contents
- Use when
- Audit steps
- The ten hijacks
- Related

Ten levers interface can pull to take person's attention vs own interest: how each works + counter to each. Ten = previously named list; each answered elsewhere in knowledge base (linked per lever). Counters serve ../principles/respectful.md humane-design principle.

## Use when
- Auditing feature for attention capture.
- Choosing counter to lever feature pulls.

## Audit steps
1. List levers feature pulls (ten below).
2. Per lever → first decide: respects or exploits human sensitivity behind it?
3. Then apply counter-pattern from lever's linked pattern file(s).

## The ten hijacks

### 1. Menu control
- Mechanism: option-writer frames question → choice feels free while alternatives never appear.
- Counter: audit what option set omits; name omitted options; full catalog one tap away.
- Detailed in: ../patterns/defaults-and-choice-architecture.md; ../patterns/recommendations-and-personalization.md (ranking).
- Hypothetical: health-insurance enrollment wizard shows only premium plans as 'your options' → names omitted basic plans + links all plans.

### 2. Variable reward
- Mechanism: unpredictable payoff each pull, tap/refresh → trains compulsive checking.
- Counter: batched delivery, predictable schedule.
- Detailed in: ../patterns/feeds-scrolling-and-pacing.md.
- Hypothetical: job-alert app drips matches at random → batched into one alert at set time.

### 3. Fear of missing out
- Mechanism: vague dread of losing something important keeps people in loop.
- Counter: visible end, e.g. 'all caught up' marker; digest at person-chosen time.
- Detailed in: ../patterns/notifications-and-interruptions.md; ../patterns/feeds-scrolling-and-pacing.md.
- Hypothetical: community-events app hints 'things are happening' w/o specifics → end marker once all new events seen + digest at member's scheduled hour.

### 4. Social approval
- Mechanism: faces, counts + reactions turn belonging into score.
- Counter: no approval gate on receiving; following separate from liking; never present public count as measure of person's worth.
- Detailed in: ../patterns/recommendations-and-personalization.md; deceptive-patterns.md.
- Hypothetical: student-portfolio site: students get feedback only after peers like their work; site ranks profiles by like totals → feedback reaches everyone; follow separate from like; no total shown as student's standing.

### 5. Reciprocity
- Mechanism: implied debt (tag, endorsement, read receipt) obliges reply.
- Counter: no prompted endorsements, tags/invitations in person's name; presence signals opt-in.
- Detailed in: ../patterns/notifications-and-interruptions.md; deceptive-patterns.md.
- Hypothetical: team chat tool shows read receipts by default + prompts users to 'thank back' colleagues → receipts + presence off until turned on; no prompted messages in user's name.

### 6. Bottomless feed
- Mechanism: list refills itself → moment of choosing to stop never arrives.
- Counter: Load More + pagination; show seen count.
- Detailed in: ../patterns/feeds-scrolling-and-pacing.md.
- Hypothetical: real-estate app endlessly refills listings → paginated results w/ 'seen so far' count.

### 7. Instant interruption
- Mechanism: everything buzzes on arrival, because interrupting pays sender better than waiting.
- Counter: message urgency sets delivery modality; asynchronous by default.
- Detailed in: ../patterns/notifications-and-interruptions.md.
- Hypothetical: hospital shift-scheduling app buzzes for every swap comment → only urgent coverage gaps interrupt; rest waits in inbox.

### 8. Bundled reasons
- Mechanism: person's errand routed through company's goals.
- Counter: direct route to person's own intent, skipping feed + notification center.
- Detailed in: ../patterns/feeds-scrolling-and-pacing.md.
- Hypothetical: banking app routes 'check balance' via promotional-offers screen first → balance reachable directly, w/o passing feed/notification center.

### 9. Inconvenient exit
- Mechanism: leaving costs far more effort than arriving.
- Counter: symmetric exit = same channel, same steps + one honest confirmation.
- Detailed in: ../patterns/defaults-and-choice-architecture.md; deceptive-patterns.md.
- Hypothetical: museum membership bought online, cancellable only by phone → online cancel w/ same steps as joining, one honest confirmation.

### 10. Foot in the door
- Mechanism: small first tap opens something much larger than advertised.
- Counter: state time, steps + scope before click.
- Detailed in: ../patterns/feeds-scrolling-and-pacing.md; ../patterns/transparency-and-honesty.md (data, algorithms + business model).
- Hypothetical: tax office 'quick question' chat opens full intake interview → link states expected time, steps + interview scope before tap.
