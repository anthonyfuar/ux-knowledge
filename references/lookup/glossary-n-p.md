# Glossary N-P

Usability + humane-design terms, N to P. Open when term needs exact meaning or finding/rationale needs exact wording.

## Terms
|Term|Meaning|See|
|---|---|---|
|Nash equilibrium (selfish routing)|Each person's best individual choice leaves everyone worse off; happens when product reaches full adoption|../evidence/unintended-consequences.md|
|Negative externality|Cost imposed on people not party to transaction|—|
|Negativity bias|Vs equivalent good events, bad events weigh more + get recalled more sharply|../laws/cognitive-bias.md|
|Occam's Razor|Tie-breaker by assumption count: option taking least on trust preferred, provided rivals level w/ it on predictive power|../laws/occams-razor.md|
|Operational transparency|Revealing behind-the-scenes work (steps, how estimate gets computed) makes consumers value product more; documented 2011|../patterns/transparency-and-honesty.md|
|Opt-in vs opt-out|Data collection/add-ons off until person chooses them vs on until person refuses them; humane design favors opt-in|[Principles index](../principles/index.md)|
|Outcome primacy|First reward has outsized effect on later choices|—|
|Page parking|Opening candidate pages in separate tabs to look at later|—|
|Paradox of the Active User|People start working immediately + leave manuals unopened, though learning first would save them time|../laws/paradox-of-the-active-user.md|
|Pareto chart|Bar chart of contributors sorted by size + cumulative-percentage line; 80% cut-off marks contributors to prioritize|../methods/pareto-chart.md (how to build one)|
|Pareto Principle (80/20)|Outcomes concentrate in minority of drivers: 20% of causes account for ~80% of effects|../laws/pareto-principle.md|
|Parkinson's Law|Work expands to fill time allotted to it|../laws/parkinsons-law.md|
|Peak-end reference price|Internal price benchmark behaving like weighted blend of highest + most recent price seen|../laws/peak-end-rule.md|
|Peak-End Rule|Most intense moment + ending mainly decide how experience gets judged|../laws/peak-end-rule.md|
|Perceived performance|How fast system feels; shaped by animation, progress bars + even deliberate delay|../patterns/feedback-loading-and-performance.md|
|Perceptual load|Main task's relevant perceptual demand: high load blocks distractors, low load lets them in; theory from 1995|../laws/selective-attention.md|
|Periphery of attention|What people track w/o focusing on it; can hold far more than center + its items can get promoted to center when needed|[Principles index](../principles/index.md)|
|Persona spectrum|Viewing one limitation as permanent, temporary or situational → reveals true audience size|../patterns/inclusive-and-accessible-design.md|
|Personalization paradox|People reluctant to hand over personal data, yet time-saving tailoring runs on it|../evidence/personalization-and-surveillance.md|
|Pertinence|Item's current importance given user's goals; pertinent items break through attention filter (shown 1963)|../laws/selective-attention.md|
|Phi phenomenon|Apparent motion from static stimuli shown alternately; described 1912; why frame-based animation reads as motion|../laws/gestalt-principles-overview.md|
|Poka-yoke|Mistake-proofing: disabling/locking control when using it would cause danger|../patterns/errors-and-input-tolerance.md|
|Positive friction|Resistance added deliberately, in measured dose → person pauses to reflect, accidental actions stopped + mistakes prevented|../patterns/friction-undo-and-confirmation.md|
|Positive test strategy|Testing only cases where one's hypothesis predicts yes; described 1987|../laws/cognitive-bias.md|
|Postel's Law (Robustness Principle)|System output must match expected form exactly; input tolerated even when it varies. Began as robustness rule for network software|../laws/postels-law.md|
|Power law of learning|Task time falls w/ repetitions along power curve (straight line on log-log axes). Saturation point (plateau) = point past which more practice barely helps|—|
|Prägnanz|When image complex or open to several readings, people see its plainest version|[Prägnanz](../laws/pragnanz.md)|
|Premortem|Session before work starts. Steps: 1. treat plan's failure as already happened → 2. list reasons for it → 3. prioritize them → 4. assign owner to each|../methods/premortem.md (how to run one)|
|Prime pixel; infinite edge|Prime pixel = pointer's current or most likely location, where next movement begins. Infinite edge (magic pixels) = screen boundary mouse cannot cross acts as target of unbounded depth; does not hold on touch screens|../laws/fittss-law.md|
|Product tour|Up-front overlay sequence explaining features; clashes w/ active users (they start working w/o reading)|../patterns/onboarding-and-first-use.md|
|Progress indicators|Activity (indeterminate) indicator = shows work happening w/o percentage. Heartbeat indicator = driven by real work → if it stops, halt itself signals hang|../patterns/feedback-loading-and-performance.md|
|Progressive disclosure|Essentials shown by default; extras one step away; means incl. hover menus, toggles, accordions + dropdowns|../patterns/complexity-management.md|
|Progressive onboarding|Mastering one step unlocks next feature → features arrive one at a time|../patterns/onboarding-and-first-use.md|
|Prospective hindsight|Causes hunted more sharply when future outcome framed as already past|../methods/premortem.md|
|Proximity|Objects grouped by closeness → spacing carries meaning|../laws/proximity.md|
|Pseudo-localization|Expanding placeholder text (e.g. to twice source length) or mirroring it, to test layouts before translation|../patterns/inclusive-and-accessible-design.md|
