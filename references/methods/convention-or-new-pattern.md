# Convention or new pattern

## Use when
- New interface pattern: worth its learning cost?
- Redesigning familiar product.
- 5 steps: convention by default → novelty only for named purpose → audience research → test over repetitions → opt-in rollout.

## Decision flow
- No named purpose for departing → keep convention.
- Named purpose but no audience research yet → research first (step 3).
- Usability always outranks originality → new pattern hurting usability in testing → back to drawing board.
- Redesigning something people already know → time-limited opt-in, not forced switch.

## Steps
1. **Default to convention** (Jakob's Law). Why: pays off in sign-ups, task completion + conversion; users apply models they already own + stop noticing interface.
2. **Depart only for named purpose.** Valid purposes:
|Purpose|Hypothetical|
|---|---|
|Differentiation from competitors|Hypothetical: household-budgeting app built around timeline of upcoming bills, not usual account list.|
|Disruption w/ new technology|Hypothetical: home-insurance claim: person photographs damage, system drafts claim, not long form.|
|Exploration / surprise|Hypothetical: city-library site: browsing opens as walk along virtual shelves, w/ surprise pick from shelf beside each book.|
3. **Study audience before any departure**: behavior, preferences, needs.
   - Research mental models w/ a few think-aloud sessions (usually enough) + card sorting.
   - Mental models largely unconscious → find them in users' mistaken expectations + wrong predictions, not self-descriptions.
   - Audit dominant conventions of users' most-visited sites + apps; align navigation, search, cart + forms w/ them.
4. **Test novel pattern rigorously**: measure learning curves over repeated use, not first use only. Novel pattern harming usability → rethink.
5. **Roll out familiar-product redesign as opt-in for limited period**, not forced switch. Include: way back, way to comment, advance view of new version before switching.

## Cases
|Case|What happened|Lesson|
|---|---|---|
|YouTube, 2017 desktop redesign|Opt-in for limited period, w/ way back, way to comment, advance view.|Step 5 as described.|
|Snapchat, early 2018 redesign|Forced switch; once people could no longer find everyday features → share of users moved to Instagram + mass protest.|Cost of forcing switch on familiar product.|

## Output
- Named purpose for each departure (or decision to keep convention).
- Research notes on audience mental models + dominant conventions.
- Learning-curve results over repeated use.
- Rollout plan: opt-in window, way back, comment channel, advance view.

## Pitfalls
- Judging novel pattern on first use only → measure over repetitions.
- Asking users to describe their mental model → watch mistaken expectations + wrong predictions instead.
- Forced switch on familiar product → opt-in w/ way back.
