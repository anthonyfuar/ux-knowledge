# Measure what you value

## Use when
- Choosing, reading / reporting metrics so they reflect value to people, not only activity.

## Rules
|Situation|Do|Avoid|Why|
|---|---|---|---|
|Setting well-being goal|number + owner + dashboard place|goal w/o all three|w/o them it gets traded away|
|Planning mitigations|baseline unhealthy behaviour now: late-night use, compulsive checking, regret|starting to measure only after fix|later mitigations need baseline to show movement|
|Reporting affected people|headcounts|percentages|small share of huge base = many people|
|Judging result|assess: several quantitative signals + sentiment + qualitative research + population segments + single powerful stories|one metric alone|maximizing any metric taken alone can produce harm|
|After experiment|segment results → find losing groups|reading only average|—|
|Staying close to problems|sit product teams w/ support staff|keeping teams apart from support|they hear what average hides|
|Before acting on data|name missing variable; in review, say it aloud + decide whether to go find it|acting on collected data as if complete|accurate, current figures can still point wrong way when decisive quantity never collected|
|Claiming impact|reach for outcome outside product|in-product signals only|in-product signals = proxies for what person wanted: money kept, skill acquired, night slept, problem settled|
|Reporting usage|normalize hours of use by run time; say plainly hours of use alone do not mean success|raw hours as win|—|

## Observing the real-world outcome
1. Decide at project start how to observe real-world result.
2. Ways to observe it:
   - linked record person agreed to share;
   - measured sample, not whole population;
   - comparison against group never getting feature.
3. Self-report alone = weakest way; never let it carry claim by itself.
- Caveat: product can move its in-product proxy while person's real outcome stays flat.

## Check questions
- Each well-being goal has number, owner + dashboard place?
- Baseline of late-night use, compulsive checking + regret taken before mitigations?
- Affected people stated as headcount?
- Which segment lost in last experiment?
- Which variable missing from this dataset; will someone go get it?
- Decided at project start how to observe outcome outside product?
- Any claim resting on self-report alone?
- Hours of use normalized by run time + labelled as not success in themselves?

## Hypothetical examples
- Hypothetical (headcount): national tax portal finds confusing filing step trips up small share of its users → report states how many people make up share, not percentage.
- Hypothetical (missing variable): commuter-rail dashboard shows trains on time all week, arguing service fine — until someone asks how many riders got left on platform by full trains, figure never collected.
