# Miller's Law

## In one line
Working-memory (WM) span, averaged over people = ~7 ± 2 items at once; later research argues capacity smaller, nearer 4 (~four). Rule: chunk content; never cap menus/lists at seven. Matters most when sizing chunks, refusing arbitrary "seven item" caps, formatting long strings.

- Class: effect or principle. Theme: Memory, within group Memory and cognition.

## Applies when / does not apply when
|Applies when|Does not apply when|
|---|---|
|immediate memory span: how much people hold at once|counting how many items screen shows: number = reason to chunk, never a cap|
|absolute judgment: identifying one stimulus level w/o reference|menus + on-screen options: scanned + recognized, not memorized|
|sizing chunks, formatting long strings|as fixed capacity: prior knowledge + circumstances (setting) shift how much short-term memory holds|
|setting how many levels one encoding (shade, size, tone) can carry|as one number for everyone: capacity differs by person + context|

## Which number to cite
Cite limit fitting claim. 7±2, 4–7 chunk range + later ~four estimate = different claims: name figure cited; never merge into one "rule".

|Figure|Meaning|Conditions / caveat|
|---|---|---|
|7 ± 2|1956 ceiling for two separate things: absolute-judgment capacity + immediate memory span|averaged over people; counts chunks, not items|
|4–7 chunks|chunk range|claim distinct from 7±2 + ~four|
|~4 chunks|revised estimate, young adults; central capacity in embedded-process model (2001, 2010)|lower for children + older adults|
|~3-5 chunks|central limit when rehearsal, grouping + sensory traces blocked|central-store estimate under tightly controlled conditions; real-task span varies w/ strategy|
|3-4, ~4-6 (1975), as few as 3 (1999), 7|explainers' figures|from different tasks + conditions|
|~7 digits, 6 letters, 5 words (~9 binary digits)|span by material|depends on material|
|~2.6 bits, ~6.5 categories|absolute-judgment on one dimension|range ~3-15 categories|

## Decision rules
Chunking
- If content long → small groups: remembering, understanding + processing all easier.
- Chunk at every scale: strings → split long character runs into groups (see Hypothetical: grouped reference code); page → evident hierarchy + distinct-looking modules; text → headings, moderate overall + line length.
- If choosing labels → short, familiar, pronounceable; long/unfamiliar terms use more span.
- Chunked layouts = accessibility aid, not only convenience.

Caps + counts
- If seven-item cap proposed for menus/lists → refuse: seven backs no arbitrary design limit; not hard design rule.
- If results would paginate at ~five items → do not: only adds paging + comparison work.
- If rehearsal not possible (brief toasts, auto-advancing content, spoken prompts, dense reading) → plan ~4 new chunks at once.
- Plan ~4 new chunks at once, not 7, especially for brief or unpredictable displays.

Encodings + judgments
- If users must identify one encoding's level (legend shades, icon sizes, alert tones) alone → ≤ ~5-6 levels.
- If encoding has levels → add reference scale or side-by-side comparison → relative, not absolute, judging.
- If users must tell key categories apart → make them differ redundantly, e.g. shape + color + label.
- Before brief display, timed task or comparison → name attribute to look for first.
- If users would mentally combine interacting variables (plan comparisons, dashboards) → avoid > 2-3; pre-compute comparison or show small multiples.

Citing
- Cite Miller's Law for "group information meaningfully", not magic count: emphasis = chunking.

## Why it works
1. Limited channel: memory + judgment act like limited-capacity channel; overflow → errors. Channel capacity = bits reliably carried in given time; beyond it → confusion + wrong judgments.
2. Bits: one of 2 equally likely alternatives = 1 bit (bit's definition); one of 16 equally likely = 4 bits = 4 successive binary decisions.
3. Two separate limits (1956): absolute-judgment span roughly constant in bits; immediate-memory span roughly constant in chunks, whatever each chunk holds.
4. Chunks, not bits: short-term memory = exception to constant-capacity-in-bits model (held for some other tasks) → capacity counted in meaningful chunks. Chunking packs more meaning into limited slots; when material forms meaningful wholes, more fits.
5. Practical vs central span: everyday span inflated by rehearsal, grouping, attention control + brief modality-specific sensory traces (2001 paper + 2010 review separate practical span from central limit).
6. Embedded-process model (2001, 2010): WM = activated long-term memory w/ limited focus of attention; central capacity ~4 chunks.
7. absolute-judgment = identifying stimulus level on one dimension, no reference to compare against.

## Misreadings and limits
- Wrong (misapplication; laws: Miller's Law, Chunking): cap menus, results, dropdowns, slides or radio groups at five to seven items, e.g. menu capped at seven. → Right: 2000 critique called such limits superstition; seven = reason to chunk, not limit; capacity possibly nearer four; on-screen options recognized, not memorized.
- Wrong: 7 ± 2 counts items. → Right: counts chunks.
- Wrong: 7±2, 4–7 + ~four = one rule. → Right: different claims; name the one meant.
- Wrong: absolute-judgment span, attention span (~6 objects per glance) + immediate-memory span = one process. → Right: basic mistake, per 1956 paper; seven recurring across them probably coincidence.
- Wrong: "chunk" precisely defined. → Right: 1956 paper itself admitted its chunk definition vague.
- Wrong: paper from 1958 (or 1955). → Right: cite 1956; 1955 = invited-address date.
- Wrong: capacity fixed. → Right: prior knowledge + circumstances shift it; differs by person + context.
- Limit: 3-5 chunks = central store under tightly controlled conditions; real-task span varies w/ strategy.
- Limit: explainer figures (3-4, ~4-6 from 1975, as few as 3 from 1999, 7) come from different tasks + conditions.

## Check questions
- [A] (Chunking, Miller's Law): chunks easy to scan, hierarchy plain? Look for walls of text, unformatted numbers/codes, dense layouts w/o modules or dividers.
- Every capacity claim names its figure (7±2, 4–7, ~four, 3-5)?
- Any menu, list or results page w/ count limit justified only by "seven"?
- Where users must identify one encoding's level alone: ≤ ~5-6 levels, or reference scale / side-by-side comparison offered?

## Symptoms → fixes
|Symptom|Likely cause|Fix|
|---|---|---|
|Menu or list trimmed to seven "because of Miller's Law"|number used as cap|drop cap; chunk + group meaningfully instead|
|Long code or number misread or re-asked|unbroken character run|split into groups; format long strings|
|Legend shades, icon sizes or alert tones confused|too many levels for absolute-judgment|≤ ~5-6 levels; add reference scale or side-by-side comparison; code key categories redundantly|
|Users cannot compare plans or dashboard figures|> 2-3 interacting variables to combine mentally|pre-compute comparison or show small multiples|
|Results paginated at ~five items|count cap taken from "seven"|drop five-item paging: only adds paging + comparison work|
|People miss content in toasts or auto-advancing screens|no chance to rehearse|~4 new chunks at once|
