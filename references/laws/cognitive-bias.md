# Cognitive Bias

## In one line
Cognitive bias = systematic judgment error from mental shortcuts; often unconscious. Strict sense: perception + decision soundness both tilted, cause = reasoning/judging misfiring in same pattern repeatedly. Use when: framing choices, prices, defaults, consent; guarding team decisions + research readings vs confirmation/framing/complexity bias; checking if bias sturdy enough to cite.
- Class: construct (not law/effect). Aliases: none.
- Theme: Decisions. Matters most for: choice framing; guarding team decisions vs confirmation + complexity bias; moments memory distorts.
- Core stance: design around biases → users protected, not exposed. Watch design team's own confirmation + complexity bias, not only users'.

## Applies when / does not apply when
|Situation|Bias in play?|Note|
|---|---|---|
|any judgment by users/design team|yes: biases affect both alike|assume both use mental shortcuts|
|person notices nothing wrong|yes: biases act outside awareness|awareness helps catch, never removes|
|routine action: familiar, predictable, low-effort|runs entirely on System 1 → shortcuts dominate|deliberate thought for high-stakes moments|
|framed choice; people care little + know little about matter|framing effects strongest|frame neutrally|
|wanted outcome + emotional topic + deeply held belief|confirmation bias strongest|outside review|
|trained domain user acting on recognition|not heuristic: expert intuition = recognition|keep layouts, cues + positions stable|
|flawed argument|not bias: bias = processing error; logical fallacy = argument's structural flaw; distinct things|—|
|sturdy bias in new context|context can reverse even sturdy bias tendency|test by experiment|

Heuristics themselves useful; problem = hidden errors they produce, not heuristic use.

## Decision rules

### Stance + testing
- Assume users + designers both use mental shortcuts; awareness helps catch biases, never removes them.
- Costly decisions, broken logic + unintended discrimination each less likely once people can name common biases (named bias easier to catch in self/others) → learn common biases.
- Test every bias-reliant design treatment by experiment, regardless of team's confidence it works.
- When applying bias → account for situation + individual.
- Before choosing bias remedy → diagnose user's problem: one of mind's 4 (acting fast under time pressure; too much information; filling in missing meaning; choosing what to remember).

### Frames, defaults + emphasis
- Frame consent prompts, settings labels + survey questions neutrally.
- Default never neutral.
- Visual emphasis in quick decisions acts as default → use for user's goal.
- Consequential choice w/ attractive presentation → decision-relevant facts next to it.
- Multi-step choice → running total + combined consequence at every step.

### Numbers, ratings + base rates
- Show base rates (sample sizes, true outcome frequency) next to vivid cues.
- Show review count next to every rating.

### Now vs later
- Bring long-term benefits of choices (e.g. backups, security setup, saving) into present.
- Never use "now" rewards user's future self would reject.

### Experts vs novices
- Trained domain users acting on recognition → keep layouts, cues + positions stable.
- Novices → explicit guidance; w/o recognition they fall back on heuristics.

### Team research + decisions
- Small-sample results feel more replicable than warranted → report counts + intervals; replicate before acting.
- Research synthesis → count incidents; do not weight most memorable clip or loudest complaint.
- Watch for confirmation bias in own research synthesis + stakeholder debates.
- Build external review into design decisions, not self-audit: people rarely see own bias.
- Add short, feedback-based debiasing to design critiques + research synthesis.

## Why it works

### Mechanism
- Hidden judgment tilt = price users + designers alike pay for speed: experience condenses into rules of thumb replacing full case-by-case weighing.
- Shortcuts as budget move: charge = unseen, patterned skew in assessing, recalling + picking; gain = mental effort saved for creative work + hard problems.
- Biases directional: systematic errors point one way → survive averaging across many users.
- Causes: "cold" (heuristics, noisy processing) + "hot" motivational (e.g. wishful thinking).
- Given ecological rationality + error management, bias can count as both defect + adaptation.
- Outside observer spots person's errors more readily than person does.
- Bias susceptibility stable over time but can drop w/ training.

### Two systems
- System 1 = fast, automatic, effortless, involuntary; continuously feeds impressions to System 2.
- System 2 = slow, effortful; usually endorses System 1's offers w/ little change.
- System 2 takes over only when System 1 has no answer, when surprise breaks System 1's world model, or when error imminent. Surprise alone summons System 2.
- System 1 weak at logic + statistics.
- System 1 never switches off → illusions persist even when known as illusions.
- Fast thinking covers both expert + heuristic intuition; slow, effortful thinking starts only when neither yields answer.
- Expert intuition = recognition, not heuristic: cue accesses stored knowledge; knowledge supplies answer.
- Confidence not proof of expertise: people often confident when wrong.

### Four problems
- Widely used grouping files biases under 4 problems mind solves: acting fast under time pressure; too much information; filling in missing meaning; choosing what to remember.
- In it, each bias = shortcut solving one of 4 problems + misfiring when context changes.

### Origin
- Prompt for 1972 work: gut estimates fail when numbers differ by many powers of ten.
- Concept dates to 1972: entered literature via 1972 paper finding people judge how likely something seems by resemblance to typical case; support = this 1972 paper + replicable experiments.
- Heuristics = proposed cause: errors (can run in fixed direction + prove severe) = price of speed heuristics give in judging uncertain-event odds. Proposed to explain: rational choice theory kept mispredicting real judgment, across experiments others could repeat.
- Research line: 1974 review of judgment under uncertainty; 1979 prospect theory (losses outweigh gains); 1981 decision-framing work; 1982 edited volume collecting it.
- Framing rests on prospect theory (1979) + 1981 framing work.
- Confirmation bias traces to 1960 2-4-6 task.
- System 1 / System 2 labels: coined by other dual-process researchers; popularized by 2011 book on two thinking modes.

## Bias terms
|Term|What happens|Design rule|
|---|---|---|
|Confirmation bias|held belief steers information search, interpretation + recall; challenging information dismissed. Acts at 3 points: biased search (only yes-expecting questions), biased interpretation (stricter standard for unwelcome evidence), biased recall. Mostly automatic. Welcome claim tested by "can I believe it?", unwelcome by "must I believe it?". Side effect: on polarizing topics, arguing on merits gets very hard. One example of cognitive bias|watch own research synthesis + stakeholder debates; outside review|
|Complexity bias|team cost: going elaborate excuses team from grasping problem itself; tell-tale = leaning to intricate solution. Two routes: (a) confused/novice person takes easy for hard; (b) intricacy alone earns idea credit for depth/cleverness. Popular article (8 January 2018) definition: intricacy taken as proof of expertise, deep understanding or intelligence = frequent reason plain answers lose to elaborate ones|pull toward complexity = cue to observe longer before adding assumptions|
|Affect heuristic|judgments + choices follow likes/dislikes, w/ little deliberation. Appealing brand/visual can replace value/risk assessment = halo like Aesthetic-Usability Effect|consequential choice → decision facts next to attractive presentation|
|Attribute substitution|System 1 swaps hard question for easier one + answers it instead|—|
|representativeness heuristic|probability judged by resemblance to stereotype; base rates ignored|base rates next to vivid cues|
|Availability heuristic|frequency judged by ease of recalling examples|count incidents in synthesis|
|Anchoring|first number seen (first price, default quantity, slider start) becomes reference; people adjust too little from it, even when irrelevant|honest first reference price|
|Framing|same facts as gains or losses → different reference points → different choices|neutral consent prompts, settings labels, survey questions|
|Status quo bias + defaults|current state = reference → any change coded as potential loss|default never neutral|
|Loss aversion|loss felt roughly twice as strongly as same-size gain|cancelling as easy as joining|
|Endowment effect|ownership adds attachment|—|
|Omission bias|harm from acting feels worse than same harm from not acting|—|
|Base-rate neglect|sample size behind figure ignored|review count next to every rating|
|Narrow framing|each decision judged alone, not as part of whole → small add-ons/upgrades each looking acceptable can sum to choice user would reject if shown all at once|running total + combined consequence at every step|
|Present bias|immediate payoffs pull harder than later ones → choices inconsistent over time|bring long-term benefits into present|
|Memory biases|subclass of cognitive bias; Peak-End Rule = one of them|—|
|Bias blind spot|people see biases in others more than in themselves|self-check for design teams|
|G. I. Joe fallacy|mistaken belief: awareness of bias neutralizes it|↑|
|Inattentional blindness|focused attention hides otherwise conspicuous stimuli; classic demonstration: many viewers counting passes in ball-game video miss costumed person walking through scene|—|
|Ecological rationality|heuristic can prove accurate when fitting its environment's structure|—|
|Error management theory|proposes judgment tilts toward cheaper mistake|—|

## Misreadings and limits
- Wrong: awareness of bias removes it → Right: awareness only improves odds of catching it; even after learning of it, bias may stay (G. I. Joe fallacy).
- Wrong: averaging many users' judgments cancels bias → Right: systematic errors point one way + survive averaging.
- Wrong (framing): reporting percentages from 20-user tests → Right: report counts w/ confidence intervals + view result in flipped frame too.
- Wrong: listed bias = fact → Right: catalogues mix sturdy effects w/ weak/disputed ones.
- Wrong: sturdy bias works same everywhere → Right: context can reverse even sturdy bias tendency.
- Wrong: loss framing always motivates → Right: loss framing can irritate instead; loss-framed retention copy can backfire as reactance.
- Wrong: confidence proves expertise → Right: people often confident when wrong.
- Wrong: heuristics = problem → Right: heuristics useful; problem = their hidden errors.

### Overstating evidence
- Parkinson's Law from humorous essay, not research.
- Pareto Principle's 80/20 ratio approximate.
- 1982 figures behind Doherty Threshold written by vendor.
- Goal-Gradient Effect rests on animal studies + 2006 human field study w/ real rewards (customers speeding up more toward first reward more likely to earn another + came back sooner). Never restate it as finding on why people drop out.
- 1989 rule-discovery study illustrates complexity bias well (most participants offered rules more elaborate than hidden one, merely any 3 ascending numbers), but own conclusion = reasoning strategies shift w/ task; citing it as complexity-bias proof misreads it. Three-number task itself dates to 1960, not 1989.

## Check questions
[A] = answerable from artifact itself; [P] = needs process/research evidence.
- [P] (Cognitive Bias) Does design counter known biases, not rely on them? Look for: designer confirmation bias in research; complexity bias in solutions.
- [A] (status quo bias, loss aversion) Defaults = what informed user would choose + easy to change? Look for: pre-checked add-ons; self-serving opt-outs; buried settings.
- [A] (loss aversion) Leaving/cancelling as easy as joining? Look for: multi-step cancellation; guilt-laden or loss-framed retention copy.
- [A] (automation bias) Can user cheaply verify AI output before accepting it? Look for: missing confidence cues/sources; one-click acceptance of high-stakes suggestions.
- Team self-check: seeing bias only in others (bias blind spot)? Believing awareness of bias neutralizes it (G. I. Joe fallacy)?
- Before choosing remedy: which of 4 problems (acting fast, too much information, missing meaning, what to remember) user solving?
- Before citing bias: among sturdy effects, or weak/disputed?

## Symptoms → fixes
|Symptom|Likely cause|Fix|
|---|---|---|
|Pricing/plan page steers people to tier they do not need|Choice Overload decoy; anchoring|compare tiers vs user's stated criteria; drop dominated tiers; show honest first reference price|
|Users stuck w/ defaults or trapped in subscriptions|status quo bias, loss aversion|default = what informed user would pick; cancelling as easy as signing up; no guilt copy|
|Team reads small test result as decisive|framing, bias blind spot|flip frame; report counts w/ confidence intervals; get outside review|
|Checkout quietly adds cost/consent|defaults, status quo bias|add-ons + card saving unchecked by default; all fees visible before review step; apply influence-vs-manipulation test|

## Hypothetical examples
- Hypothetical: affect heuristic → person picks health-insurance plan because its app feels warm + friendly, answering "do I like this app?" not "does this plan cover my prescriptions?".
- Hypothetical: base-rate neglect → school-comparison page lists one school's top exam pass rate w/o noting it comes from one small class; parents rank it above school whose slightly lower rate covers many classes.
- Hypothetical: complexity bias → travel-booking team, seeing users abandon checkout, drafts multi-factor hesitation model; watching sessions longer shows plain cause: date picker hides return-date field.
- Hypothetical: loss framing backfires → clinic portal tells patient never missing appointments she will lose her slot unless she confirms within the hour; she feels distrusted + annoyed, not prompted.

## Humane bound
- Bounded by Transparent; Intentional (governs default effect); Empowering (leaving must match joining in ease).
- Status quo bias exploited for conversion: pre-checked add-ons; opt-outs serving company; buried settings.
- Loss aversion exploited for retention: multi-step cancellation; guilt-laden or loss-framed retention copy (can backfire as reactance).
- Anchoring exploited: struck-through reference prices + first amounts shown only to inflate spending.
- Named deceptive patterns exploiting biases: sneak into basket; opt-out defaults + pre-ticked consent; roach motel; confirmshaming.
- Never use "now" rewards user's future self would reject.
- Further reading: deceptive-pattern taxonomy; defaults + choice architecture patterns; transparency of data, algorithms + business model patterns (run their "if they knew" test); influence vs manipulation.
