# Serial Position Effect

## In one line
First items (primacy) + last items (recency) of series recalled + remembered best. Use when ordering items people meet once in sequence (spoken menus, onboarding steps, lists read before deciding), choosing what sits at ends of bar or list, keeping information intact between showing + using it, or checking whether Serial Position = right law to cite.
- Covers: primacy effect + recency effect. Class: effect/principle.
- Theme: Memory. Most affects: order of items met once (spoken menus, onboarding, lists read before deciding) + the few anchor items at bar ends.
- Core rule: anchor 1-2 key items at ends of navigation bar or list; mid-list slots to lowest-priority entries; order rest by task frequency or known key.

## Applies when / does not apply when
|Situation|Serial position?|Order by|
|---|---|---|
|items met once in order: spoken menu, onboarding steps, list read before deciding|yes: recall effect|key items first + last; low-priority entries between|
|visible navigation scanned repeatedly|no: recognized, not recalled (same reason Miller's Law does not cap menu length)|task frequency + known keys (alphabetical, chronological)|
|long list|—|known-key order|
|menu|—|frequency order|
|a few anchor items|yes|ends|
|spoken vs written list|recency stronger for spoken lists (modality effect)|—|
|decision > ~30 s after exposure (e.g. user leaves page + returns)|primacy survives delay, recency does not|most important item first|
|decision right after reading|last item favored|—|
|video, audio + other content user does not pace|—|usually end on key point|

## Decision rules

### Order the items
- Use bar/sequence ends for 1-2 items users must find w/o scanning; order remaining items by task frequency or known key (recall effect, not scanning rule).
- In navigation → both outer ends (leftmost + rightmost) for key actions; middle for what matters least.
- Key items never go mid-list.
- If ordering rules conflict → known-key order for long lists; frequency order for menus; ends for a few anchor items.
- Long forms + long pages → front-load essentials (attention decrement).
- Lead results, reviews, comparisons + descriptions w/ representative, accurate information, never w/ outlier.
- Lead w/ core value + make first outcomes good: order changes impressions + choices; make first-run + first-transaction outcomes clearly good.
- Repeating key items at end does not undo anchor set by start → get start right.
- Where fairness matters (survey answers, vendor lists, option sets meant to stay neutral) → rotate or randomize order.

### Match order to timing + pacing
- If decision > ~30 s after exposure → lead w/ most important item.
- If decision right after reading → last item favored.
- For video, audio + other content user does not pace → usually end on key point.
- Give key content time on screen: fast feeds + auto-advancing carousels weaken memory for early items.

### Voice interfaces
- End prompt on key option, no trailing filler; put item users will act on next at end, or keep it selected.

### Protect what people hold in mind
- No interstitials, modals or detours between showing information (code, price, instruction) + needing it; keep task-relevant state visible across steps.
- Never rely on users recalling order of steps or characters → number steps + make adjacent items distinguishable.
- Do not show partial list as memory hint when users are meant to recall remaining items.
- Multi-session journeys → reinstate learning context (same screen, recap, visual cues) to aid recall of earlier steps.

## Why it works

### Mechanism
- Series start gains from primacy, end from recency, middle from neither → recall by position = U-shaped curve, lowest in middle.
- Working + long-term memory both take in mid-list items less often → middle = slot for entries mattering least.
- Primacy = rehearsal advantage: first item rehearsed alone, second together w/ first, + so on → early items reach long-term memory. First item also stands out as start, set apart from whatever preceded it.
- Pacing: slow pacing strengthens primacy; fast pacing + long lists weaken it → fast-scrolling feeds + auto-advancing carousels erode primacy.
- Recency: final items still in working memory; last item accessed fastest partly because still in focus of attention (2006 review).
- Recency fragile: short distraction wipes it out.
- Attention decrement: middle items suffer interference from items on both sides, + attention decays over sequence.
- Longer list → more items recalled but smaller share of list (illustrative figures: 15 of 30 recalled = 50% vs 40 of 100 = 40%).
- Modality effect: recency stronger for spoken lists than written ones.
- Suffix effect: one extra spoken item after spoken list, even one needing no recall, wipes out spoken-list recency advantage.
- Irrational primacy effect: first items set working hypothesis for reading later items, even when order should not matter.
- Outcome primacy (2013 reinforcement-learning study): in repeated choices, first reward disproportionately shapes later behavior.
- Position by itself creates preference.
- Transposition errors: neighboring items swap places in recall.
- Part-list cueing (1968): showing some list items makes remaining items harder to retrieve.
- Ratio rule: recency-effect size depends on ratio of delay before recall to spacing between items → time-scale invariance: recency can reappear at long time scales.
- Temporal context model (1999, 2002): retrieval cued by context present when items learned.
- Recency effect also linked to Peak-End Rule.

### Origin
- 1885: term serial position effect coined. As first described: item's recall accuracy depends on its position in sequence; items at start (primacy) + end (recency) beat middle items.
- Support for basic claim = classic memory research (see Evidence).

|Finding|Study (year, kind, sample)|Strength + caveat|Design consequence|

## Misreadings and limits
- Wrong: treating Serial Position as scanning rule for visible navigation → Right: recall effect for items met once in order; visible navigation scanned repeatedly = recognized, not recalled → order it by task frequency + known keys (alphabetical, chronological), not serial position.
- Wrong: repeating key items at end to fix weak start → Right: does not undo anchor set by start.
- Wrong: relying on recency after detour → Right: recency fragile; short distraction wipes it out.
- Wrong: crediting serial position effect alone for move from hidden menu to visible tab bar w/ key destinations at ends → Right: poor discoverability of hidden navigation also explains such shift.
- Wrong: treating company examples as evidence (product redesigns; brands such as Nike, Apple + Electronic Arts said to use serial position) → Right: no data comes w/ them; illustrations only.
- Limit: 15 of 30 vs 40 of 100 recall figures illustrative only.

## Check questions
- [A] (Serial Position Effect) Key items at start + end of lists + navigation bars? Look for: key actions buried mid-list.
- [A] (Serial Position Effect: recency) Information uninterrupted from when shown to when used? Look for: interstitials, modals or detours before step using code or instruction.
- Before citing: items met once in order, or scanned repeatedly? If scanned → frequency + known-key order, not Serial Position.

## Symptoms → fixes
|Symptom|Likely cause (laws)|Fix|
|---|---|---|
|Key action overlooked in long list|buried in middle: neither primacy nor recency|move it to start or end; lowest-priority entries take mid-list slots|
|Code, price or instruction lost before step using it|interstitial, modal or detour erased recency|remove detour; keep task-relevant state visible across steps|
|Users mix up order of steps or characters|transposition errors|number steps; make adjacent items distinguishable|
|Callers miss key option in spoken menu|trailing filler after list (suffix effect)|end prompt on key option, no trailing filler|
|List meant to stay neutral favors its first entry|position by itself creates preference (ballot order effect)|rotate or randomize order|
|People leaving + returning remember lead but not close|decision > ~30 s after exposure: recency gone, primacy kept|lead w/ most important item|

## Hypothetical examples
- Hypothetical (spoken menu): city council phone line names most-requested service first + "speak to an officer" last; rarely used options sit in middle.
- Hypothetical (onboarding sequence): home-insurance sign-up opens w/ choosing cover level + closes w/ plain summary of coverage; optional extras between.
- Hypothetical (deliberate ordering in a product's design): museum ticket kiosk's main screen puts "Buy today's ticket" first + "Member entry" last, gift vouchers + group bookings between.
- Hypothetical (decision made later): university course listing opens w/ what course qualifies graduates for + leaves practical details (building, locker access) to end → applicants reading now + deciding days later remember lead, since primacy survives delay + recency does not.
- Hypothetical (anchors at the ends of a bar): home-thermostat app's bottom bar puts current-temperature view far left + schedule far right; less-used views in middle.

## Humane bound
- Turned against people: using order to steer choice where option set should stay neutral, exploiting how position creates preference + first items frame reading of later ones.
- Turned against people: leading w/ outlier instead of representative, accurate information.
- Turned against people: interstitials or promotional modals between showing + using information, erasing what person held in mind.
- Bounded by Transparent + Empowering: explain what orders what people see + let them steer it.
- Bounded by Respectful: what interrupts, + when.
