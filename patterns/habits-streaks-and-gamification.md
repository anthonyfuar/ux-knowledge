# Habits, streaks and gamification

## Use when
- Covers: streaks, counters, ladders, leaderboards, usage reports, rewards, reminders + their effect on vulnerable people.
- Open when designing/reviewing: any progress / gamification mechanic, usage summary, request for mechanic lifting daily actives.
- Principles served: Intentional, Finite, Resilient, Respectful, Inclusive, Empowering.

## Before designing any mechanic
- Progress mechanic sets pace of somebody's day = large claim on their life.
- Earns this claim only when: habit = something person would defend on calm day + reward tracks value received.
- If product exists to calm, rest / heal → run purpose-consistency test (transparency patterns) before designing any mechanic. Test often ends discussion.
- Read beside: notifications + interruptions (what mechanic may send + when) · feeds, scrolling + pacing (how it sits in feed) · deceptive-pattern taxonomy (tricks it can become) · monetization + growth (what changes once money rides on it).

### A counter, streak or ladder causes anxiety: change the wording or the unit? (change the unit before the copy)
- When: counter, streak / ladder produces anxiety + proposed fix = gentler wording.
- Do: redesign counted unit before changing surrounding copy. Sturdier units:

|Unit|Shape|
|---|---|
|Band|e.g. most days this month|
|Quota over window|e.g. any four sessions per week, in any order|
|Milestone ladder|caps + stops, never climbs forever|
|Accumulating headline|only accumulates, never falls, e.g. lifetime sessions, total minutes|

  - Any run-based number → secondary, or drop it.
- Avoid: keeping consecutive-days count + merely adding sympathetic message when run breaks. Streak-freeze tokens + paid streak repairs.
- Why: Intentional (also Finite). Framing cannot repair counting unit punishing ordinary life. Consecutive days = most brittle unit available. Freeze tokens + paid repairs preserve fragile unit + sell relief from anxiety it creates.
- Hypothetical: language-learning app headlines words learned to date + short milestone ladder ending at set level; skipped day changes no on-screen figure.

### Who sees the progress number? (only the person)
- When: whenever progress data exists at all.
- Do: progress data private by default. Ranking, sharing + comparison w/ friends = opt-in, not defaults. Person can hide counter / fully switch it off w/o losing product. Person can reset progress.
- If well-being / health product (mental health, mood, meditation, fitness, sleep, food, recovery) → stricter rule: sensitive-category entry for well-being + health products in abuse-resistance patterns.
- Avoid: leagues + leaderboards on for everyone. Profile publishing somebody's consistency.
- Why: Intentional (also Resilient). Public consistency record also tells controlling partner / parent when person at home.
- Hypothetical: savings app shows goal progress only to saver; sharing milestone w/ partner = switch starting off.

### How to show someone their own usage? (report w/o moralizing)
- When: showing someone their own time, pickups / session counts.
- Do: plain figures. Person says what they want from figures. Describe what product did, not what person failed to do. Settings behind reported number reachable on same screen.
- Avoid: usage summary reading as verdict on someone's discipline while every mechanic driving those hours stays on. Congratulation + reproach as only two tones.
- Why: Respectful (also Inclusive). Natural response to large usage figure = change to autoplay, notifications / feed, not appeal to willpower.
- Hypothetical: e-reader usage page states hours read this month plainly, asks whether reader wants more, fewer or same + shows auto-advance-to-next-chapter setting there.

### What happens when a run breaks? (pause allowed, break never framed as loss)
- When: designing any run; people meet illness, travel, caring duties, night shifts, religious observance / bad week.
- Do: offer planned pause. Declared rest day counts as kept, not missed. Describe return by what remains, not by losses. Reminders phrased as invitations.
- Avoid: loss-framed nudges, e.g. message warning run ends tonight. Design extracting token session before midnight only so number survives.
- Why: Intentional. Loss-framed nudge turns loss aversion against person.
- Hypothetical: language app welcomes nurse back after night-shift stretch w/ words learned so far + where last lesson stopped; no mention of days missed.

### What should the mechanic celebrate? (reward what was delivered, not attendance)
- When: deciding what mechanic celebrates.
- Do: attach progress to value person recognizes: skill reached, night slept well, piece of work finished. Say plainly when short session enough for today. Retire habit scaffolding once habit holds, not escalate it.
- Avoid: rewarding act of opening app. Targets ratcheting upward automatically → nobody ever finished.
- Why: Intentional (also Empowering).
- Hypothetical: cooking-skills app marks "can make a basic sauce unaided" once learner does it + says short practice enough for today.

### Who is the most vulnerable person facing this counter?
- When: whenever any counter ships.
- Do: name most vulnerable person facing counter. Write them into misuse cases (abuse-resistance patterns describe misuse cases; misuse-case brainstorming method has worked example). Segment every mechanic result by heaviest users, not average.
- Avoid: judging mechanic on aggregate retention.
- Why: Resilient (also Inclusive). In aggregate retention, small compulsive user group looks like success.
- Hypothetical: before shipping daily-quiz counter, money-skills app team writes misuse case for indebted user checking app compulsively + reads test results for heaviest users apart from average.

### People are not doing the action: add pressure? (diagnose the missing action first)
- When: people not doing what product exists to help them do + proposal = another reminder, counter / stronger nudge.
- Do: before adding pressure, walk this staged sequence for this one action; fix failing stage:
  1. Cue: any cue at all?
  2. Gut reaction: immediate gut reaction to cue?
  3. Judgment: did person's considered judgment favour action?
  4. Ability: could person do it right then?
  5. Timing: did timing fit person's life?
- Avoid: reading every intended-vs-actual behaviour gap as lack of motivation. Escalating reminder cadence when real problem = ability.
- Why: Empowering (also Intentional). Pressure does not answer never-arrived cue / step somebody cannot complete. Pressure only adds noise to decision person already made.
- Hypothetical: medication-reminder app: if walk-through shows evening cue lands during commute (timing stage) → each person can move it to hour they choose; no second alert.

### Declining a mechanic a stakeholder asked for: what to bring instead? (growth path, not only refusal)
- When: declining mechanic requested to lift daily actives.
- Do: arrive w/ substitute. Options:
  - something genuinely worth returning for on given day
  - opt-in reminder at hour person picked
  - sessions resuming, not restarting
  - occasional summary of what product did for person
  - first week reaching real benefit sooner
  - retention read over months, not consecutive days
- Name metric substitute should move + date for reading it. Offer staged rollout w/ holdout group to settle whether substitute works.
- Avoid: removing mechanic while growth question stays unanswered → usually moment humane recommendation gets lost.
- Why: Intentional (also Empowering).
- Hypothetical: asked for daily streak, language-app designer proposes lessons resuming where stopped + opt-in reminder at chosen hour, names monthly retention as metric + sets read date + offers staged rollout w/ holdout group.
