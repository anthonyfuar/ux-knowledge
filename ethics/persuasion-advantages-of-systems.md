# Persuasion asymmetries: advantages a system holds over a human persuader

Six persuasion asymmetries between interface + face-to-face seller: how each plays out + counterweight to each. Face-to-face seller limited in ways interface is not.

## Use when
- Auditing persuasive feature, as second pass after applying deceptive-pattern names.
- Six asymmetries = second audit, run beside deceptive-patterns.md taxonomy table (= first audit table).

## Audit step
Each advantage leaned on by feature → either remove reliance on it, or ship its counterweight right next to it.

## The six advantages

### 1. Novelty hides the intent
- Mechanism: format people have not met before reads as neutral → persuasion in it arrives unexamined. People recognize old medium's persuasive tricks but not new one's.
- Counterweight: unfamiliar surface → state plainly: beneficiary, cost + what happens next.
- Hypothetical: car's new in-dash voice ordering suggests coffee stop on route → says stop = paid placement, states price + notes ordering charges stored card.

### 2. The good name of the medium
- Mechanism: tech carries own authority → whatever it presents inherits credibility it never earned.
- Counterweight: show each item's provenance + confidence; never let container do vouching.
- Hypothetical: pharmacy symptom-checker kiosk shows paid supplement suggestions in same clinical layout as triage advice → each item shows source + confidence; clinical layout no longer vouches for paid items.

### 3. It never gets tired
- Mechanism: no salesperson follows someone home for a year, but phone does. App unopened for weeks can greet person's return w/ stockpile of stored appeals.
- Counterweight: cap how often unanswered prompt returns; silence counts as answer.
- Hypothetical: retail-banking app re-shows credit-card offer every login after it's ignored → offer stops after capped number of unanswered showings; ignoring = 'no'.

### 4. The creator writes the available moves
- Mechanism: someone persuaded by person can argue, change subject or walk away; in interface only built paths exist.
- Counterweight: build in refusal, exit + way to say something flow did not anticipate.
- Hypothetical: water utility payment-plan chat offers only plan choices → adds 'none of these', 'leave' + free-text box for situations flow did not foresee.

### 5. It works on feeling while having none
- Mechanism: warmth, urgency + disappointment applied at no cost to applier.
- Counterweight: system performs no emotion it does not have; persona limited to task needs.
- Hypothetical: tutoring app mascot acts heartbroken when student skips session → neutral reminder; plain persona sized to task.

### 6. It cannot answer for the outcome
- Mechanism: when persuasion ends badly, no one can hold software to account.
- Counterweight: name consequence owner before launch; route people to owner from inside product.
- Hypothetical: travel app rebooking assistant talks traveler into non-refundable fare → team names rebooking-outcome owner before launch; in-app link reaches owner.
