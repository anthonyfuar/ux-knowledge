# Mapping memory demands

## Use when
- Flow makes people hold goal constraints, earlier values or instructions across steps/screens.
- Goal: find each place flow asks people to remember → move each demand to external memory. 7 steps.

## Steps
1. **List every step** to goal, incl. redundant ones. Remove redundant steps, e.g. auto-focus first field; drop registration walls before content.
2. **Note what people must hold in mind** at each step:
   - goal constraints (e.g. budget, dates)
   - values from earlier screens
   - instructions
   - task state
3. **Mark items held across** screen change, interruption, or while processing similar material → likeliest memory failures.
4. **Replace each marked demand w/ external memory**: visible summaries, echoed input, comparison tables, saved lists, persistent selections, paste + autofill.
5. **Re-plan flow around ~4 new chunks at once.** Children, older, stressed users → plan for fewer than ~4.
6. **Build information architecture from users' own categories** (card sorting + tree testing); merge redundant pages.
7. **Validate w/ representative users**, not team.

## Output
|Step of flow|Held in mind|Held across change / interruption / similar material?|External-memory replacement|
|---|---|---|---|

## Hypothetical example
Hypothetical: housing-benefit application states income limit on first screen; later screen asks if household income falls under it.
- Step 2: applicant must hold limit + own figure.
- Step 3: held across screen change → likely failure.
- Step 4: show limit beside newly entered income (echoed input + visible summary).

## Pitfalls
- Validating flow w/ team → validate w/ representative users.
- One chunk budget for everyone → plan fewer than ~4 for children, older + stressed users.
- Information architecture from team's categories → use users' own (card sorting + tree testing).
