# Designing peaks and endings

## Use when
- Mapping experience's emotional journey; shaping its peaks + end, incl. high-stakes moments, waits + failures.
- 7 steps, from journey map to post-experience metrics.

## Steps
1. **Map journey in three zones** (table below).
2. **Pin down peaks**, two kinds: high-stakes moments + moments where product pays off most (enjoyment, usefulness, worth).
3. **Calm tense peaks**, for first-timers above all, w/ brand's personality: reassuring tone, wit, drawn imagery, restrained motion.
4. **End on positive note**: confirm success, show relevant details, acknowledge person's effort.
5. **Neutralize negative peaks.** Negative peaks remembered more vividly. For waits, use three levers (table below).
6. **Prepare fallbacks for failures.** Rapport w/ users can grow out of bad moment.
7. **Track peaks + endings w/ post-experience metrics.**

## Journey map zones (step 1)
|Zone|Holds|
|---|---|
|Lens|whose view: research-grounded persona, one concrete scenario, persona's expectations|
|Experience|phase timeline w/ actions inside each; mindset layer (motivations, questions, pain points, thoughts); emotion line showing peaks|
|Insights|internal owners, metrics tied to each part, opportunities|

## Wait levers (step 5)
|Lever|Do|
|---|---|
|Goal-gradient|make every step of wait visible|
|Operational transparency|give estimate + method behind it|
|Idleness aversion|give waiting person something informative + entertaining|

## Cases
|Product|Moment|What it did|Step|
|---|---|---|---|
|Uber|wait after ride request|cancellations dropped once it combined goal-gradient, operational transparency + idleness aversion (all three levers); Express POOL result → behavioral-insight method|5|

## Decision rules
- If moment irreversible / high-stakes → treat as peak; reassure, especially first-timers.
- If flow ends abruptly → confirm success + show relevant details + acknowledge person's effort.
- If people must wait → show every step, give estimate + method behind it, offer something informative + entertaining.
- If failure possible → fallback ready before it happens.
- If checking whether peak / ending works → track w/ post-experience metric.

## Hypothetical examples
- Hypothetical (high-stakes peak): confirming international wire transfer in banking app; sender cannot recall it once sent.
- Hypothetical (tense peak made reassuring, step 3): university application portal's final "Submit application" screen eases moment: warm copy line + small paper-plane drawing + extra note for first-time applicants.
- Hypothetical (positive ending, step 4): tax-filing service's closing screen after return submitted confirms receipt, lists reference number + filing date + thanks person for work spent on return.
- Hypothetical (failures to prepare for): grocery service drops delivery area, leaving some households out; clinic portal finds flaw exposing appointment notes; payroll tool goes down on pay day.
- Hypothetical (rapport from bad moment): regional transit app's outage screen says plainly live timetable down, points to posted schedule at each stop + adds light-hearted illustration in operator's own style.
- Hypothetical (post-experience metric): hotel app asks for post-stay rating to track new mobile check-in feature.
