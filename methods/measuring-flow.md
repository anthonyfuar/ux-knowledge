# Measuring flow

## Use when
- Does challenge match users' skill + do they reach flow?
- Choosing among observation, validated scales, experience sampling.
- Four steps: contextual observation → validated self-report scales → questionnaire + experience sampling → triangulation.

## Steps
1. **Prefer contextual observation** to detect flow. Analytics say little about it. Observable signs:
   - go quiet or hum
   - talk about what they do, not how
   - hard to interrupt
   - report feeling energized afterward
2. **For self-report, use validated scales** (see Instruments).
3. **Questionnaire + experience sampling.** Simple flow questionnaire measures how often flow occurs, not intensity or challenge/skill ratio. Experience sampling captures moments as they happen; open answers need coding before analysis.
4. **Triangulate** self-reported flow w/ observation. Why: flow reported after experience, not during; surveys can reflect what users think researcher wants to hear.

## Instruments
|Instrument|Measures|Note|
|---|---|---|
|Flow State Scale-2|Flow as state|Short form available|
|Dispositional Flow Scale-2|Flow as trait (disposition)|↑|
|Core Flow Scales|Alternative to full state + trait scales||
|Psychological Flow Scale (2021)|Flow across domains||
|Flow Condition Questionnaire (2013)|Seven flow preconditions||
|Simple flow questionnaire|Flow frequency only|Not intensity, not challenge/skill ratio|
|Experience Sampling Method|Moments as they happen|8 random prompts/day; 13 categorical + 29 scaled items; open answers need coding|

## If → choose
- Whether flow happens in real use → observation first.
- State vs trait → state scale vs dispositional scale.
- Flow across domains → Psychological Flow Scale.
- Whether flow conditions present → Flow Condition Questionnaire.
- Momentary data → experience sampling.
- Have only frequency questionnaire → do not report intensity or challenge/skill balance from it.

## Hypothetical example
Hypothetical: team testing tax-filing tool sees accountants work silently, speak only about return at hand, ignore colleague's question → flow signs; team then runs state scale after sessions, checks it against observations.

## Pitfalls
- Reading flow from analytics → analytics say little about it.
- Treating survey answers as truth captured during flow → reported after experience + can reflect what users think researcher wants to hear; triangulate.
